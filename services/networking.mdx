## Blocky removal

**Removed — 2026-10-02:** Blocky and its HTTP listener are gone. Its saved Komodo stack is retired; configuration remains for recovery.

UniFi at `192.168.1.1` is the DHCP/default LAN DNS server. A restricted `dns-compatibility` Komodo stack preserves DNS TCP/UDP at `192.168.1.236:53` for manually configured clients. It forwards all names to the gateway except the dedicated Home Assistant zone described below. It uses CoreDNS 1.14.6, a non-root user, no capabilities, no-new-privileges, a read-only root/config and a 64 MiB limit. No HTTP port is published; host policy limits DNS to LAN and server-local clients.

Configuration and build source are in `/home/trappserver/Documents/dns-compatibility/`. UDP/TCP local-name and public-name forwarding succeeded, including after Komodo deployment. Change manually configured clients to gateway DNS before eventually removing this compatibility address. See [completed item 09](/todo/completed#09-remove-blocky-and-preserve-client-dns-completed).

## Home Assistant local DNS

**Corrected — 2026-10-08 UTC:** UniFi's `ha.ryantr.app` entry uses Forward Domain to `192.168.1.236`, TTL 60 (legacy API type `NS`). The existing CoreDNS service answers A with local Caddy's `192.168.1.236` and returns NOERROR/no answer for AAAA, SVCB and HTTPS. Previously the gateway combined a local A override with public Cloudflare HTTPS/ECH metadata, causing Chrome's `ERR_SSL_PROTOCOL_ERROR` before authentication. This change is scoped to Home Assistant; public DNS, other UniFi records, DHCP and ad blocking remain unchanged. Do not remove the compatibility service while this forwarding policy depends on it.

Gateway and compatibility-server A/AAAA/SVCB/HTTPS checks passed; public-name resolution and advertisement blocking remain functional. Chrome reconnected to the normal HTTPS dashboard without changing browser TLS or security settings. The dedicated zone is answered locally without forwarding back to UniFi, avoiding a DNS loop. Corefile syntax/startup was verified in an isolated container before restarting only `dns-compatibility`. Protected recovery snapshots are under `/home/trappserver/codex_docs/ha-mcp-dns-repair/`. To roll back, first restore the UniFi entry to A `192.168.1.236`, enabled, TTL 0; then restore `Corefile.before` and restart the resolver. Restoring CoreDNS first while the forwarding policy remains active would create a loop.
