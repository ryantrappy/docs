Paperless-ngx runs as a three-container Komodo stack. Paperless AI is a separate container. This reference was checked on **2026-09-28**.

## Access and deployment

[Paperless](https://paperless.ryantr.app) is a public Caddy route to host port 8010, mapped to webserver port 8000. Paperless AI publishes 8087 to port 3000 and has no current Caddy route.

Komodo manages `paperless` from `/etc/komodo/stacks/paperless/compose.yaml`. The webserver, PostgreSQL database, and Redis broker share `paperless_default`. Database and broker ports are not published to the host.

Paperless AI's API connection, provider, and processing settings were not inspected.

## Storage and recovery

| Data | Host location |
| --- | --- |
| Application data | `/media/internal/sixTb/paperless/data` |
| Document media | `/media/internal/sixTb/paperless/media` |
| PostgreSQL data | `/home/trappserver/Documents/paperless/pgdata` |
| Redis data | `/home/trappserver/Documents/paperless/redisdata` |
| Consume directory | `/etc/komodo/stacks/paperless/consume` |
| Export directory | `/etc/komodo/stacks/paperless/export` |
| Paperless AI state | `/home/trappserver/Documents/paperless-ai` |

Plan updates for the webserver and database together. Preserve documents and database state together. An export directory mount does not prove that an export has run.

Consult the [Paperless-ngx administration documentation](https://docs.paperless-ngx.com/administration/) matching the installed release for export and restore procedures. A backup or restore was not tested in this inspection.

Start with webserver logs, then database and broker state:

```sh
docker logs --tail 100 paperless-webserver-1
docker logs --tail 100 paperless-db-1
docker logs --tail 100 paperless-broker-1
```

Use [Service operations](/operations/services) for the shared workflow.
