Komodo's `paperless` stack manages the Paperless-ngx webserver, PostgreSQL, Redis and Paperless AI. Authentication and connectivity were checked on **2026-10-05**; other inventory details retain their 2026-09-28 observation date.

## Access and deployment

[Paperless](https://paperless.ryantr.app) is a public Caddy route to host port 8010, mapped to webserver port 8000. Paperless AI publishes 8087 to port 3000 and has no current Caddy route.

Komodo manages `paperless` from `/etc/komodo/stacks/paperless/compose.yaml`. The webserver, PostgreSQL database, Redis broker and Paperless AI share `paperless_default`. Database and broker ports are not published to the host.

Paperless AI's API connection was verified on 2026-10-05. Its provider and processing behavior were not tested.

## Native app authentication (2026-10-05)

The approved fix is applied and persisted. Authelia bypasses only Paperless paths matching `^/api([/?].*)?$`, allowing native clients to authenticate with Paperless credentials or an API token. Protected API resources still require Paperless authentication. Browser routes require Authelia password and TOTP, then sign in to the matching existing Paperless account through trusted headers.

Komodo's saved webserver environment includes:

```yaml
PAPERLESS_URL: https://paperless.ryantr.app
PAPERLESS_ENABLE_HTTP_REMOTE_USER: "true"
PAPERLESS_ENABLE_HTTP_REMOTE_USER_API: "false"
PAPERLESS_HTTP_REMOTE_USER_HEADER_NAME: HTTP_REMOTE_USER
PAPERLESS_LOGOUT_REDIRECT_URL: https://auth.ryantr.app/logout
```

The backend publishes only `127.0.0.1:8010:8000`; use [Paperless](https://paperless.ryantr.app), not direct LAN port 8010. Paperless AI joins `paperless_default` and its persisted `.env` uses `PAPERLESS_API_URL=http://webserver:8000/api`. The Paperless-specific Caddy handler uses `route` to strip supplied identity headers before forward-auth copies Authelia's verified identity. Default directive sorting previously stripped the copied header afterward.

**Verified:** Authelia and Caddy validation passed; both Paperless containers are healthy. Existing-token API requests through local Caddy and normal hostname HTTPS returned 200 without an Authelia cookie. Missing/invalid tokens and forged identity returned Paperless 401. Browser and API-lookalike paths remained gated. Password alone was denied; TOTP enabled browser SSO and its API session; logout restored the gate. AI's saved URL and existing token reached the backend with 200. Live environment and Komodo source agree, and direct LAN port 8010 is unavailable. Database and Redis containers were not recreated; images were not upgraded; normal Komodo update settings were restored.

**Remaining:** Retry real phone login/sync with existing Paperless credentials or token, and test from a separate external network. No reboot, upload, backup or restore test was performed. Protected before snapshots and coordinated rollback instructions are in `/home/trappserver/codex_docs/paperless-auth-20261005/RESULTS.md`. Restore Komodo source, Authelia policy, AI environment and Caddyfile together if rolling back. See the [Authelia integration guide](https://www.authelia.com/integration/trusted-header-sso/paperless/).
