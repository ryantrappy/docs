Open [Scrutiny](https://scrutiny.ryantr.app) from the LAN for disk health, temperatures, and SMART history. The `scrutiny` stack runs on Komodo's **Local** server.

## Deployment

Deployed and verified on **2026-10-02**, using the upstream [omnibus Compose example](https://raw.githubusercontent.com/AnalogJ/scrutiny/refs/heads/master/docker/example.omnibus.docker-compose.yml) as the base.

| Setting | Value |
| --- | --- |
| Image | `ghcr.io/analogj/scrutiny:nightly-omnibus` |
| Container / Komodo stack | `scrutiny` |
| Web listener | `127.0.0.1:8081 → 8080`; existing Caddy LAN route |
| Bundled InfluxDB listener | `127.0.0.1:8088 → 8086`; host port 8086 belongs to Network Optimizer |
| Configuration and SQLite data | `/home/trappserver/Documents/scrutiny/config → /opt/scrutiny/config` |
| InfluxDB data | `/home/trappserver/Documents/scrutiny/influxdb → /opt/scrutiny/influxdb` |
| Device metadata | `/run/udev → /run/udev`, read-only |
| Capabilities | `SYS_RAWIO`, plus `SYS_ADMIN` for NVMe SMART queries |
| Restart policy | `unless-stopped` |
| Collection schedule | Daily at midnight in the container's time zone: `COLLECTOR_CRON_SCHEDULE=0 0 * * *` |
| Automatic updates | Disabled; apply updates through Komodo |
| Local Compose reference | `/home/trappserver/Documents/scrutiny/compose.yaml`; active definition saved in Komodo |

The existing configuration and InfluxDB data were preserved. The private pre-deployment backup is at `/home/trappserver/codex_docs/komodo-migration/scrutiny-backup-20261002/config-influxdb-before-deploy.tar.gz`.

## Collect and check

Run a manual collection:

```sh
docker exec scrutiny /opt/scrutiny/bin/scrutiny-collector-metrics run
```

The existing `/home/trappserver/Documents/scrutiny/scrutiny_manual_trigger.sh` now runs this command against the Komodo-managed container.

Check the dashboard's latest collection times after changing disks. Device names can change after a reboot or hardware change; review the stack's device mappings when adding or replacing a drive.

**Verification:** Komodo reported the service **Running**; the Scrutiny health API returned success; the HTTPS Caddy route returned HTTP 200; all 11 current disks had fresh metrics. Notification delivery and reboot behavior were not tested.
