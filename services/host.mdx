## Dynamic DNS

**Updated — 2026-10-02:** Cloudflare DDNS is the sole updater for public server A records. The Komodo `cloudflare-ddns` stack manages all thirteen current records; each matched the current WAN IPv4 address at verification.

The legacy `ddclient.service` used `protocol=dyndns2` with `domains.google.com` and was reporting failed updates. It is now stopped and disabled in systemd and legacy SysV startup. The installed package and configuration are retained for rollback; do not restart it alongside Cloudflare DDNS.

The private pre-disable configuration backup is `/home/trappserver/komodo-migration/ddclient-config-before-disable-20261002`. See [public DDNS coverage](/infrastructure/caddy#public-ddns-coverage) for current hostnames. Retired public names are not recreated; internal service names remain owned by UniFi DNS.

## Terminal access and authentication monitoring

TCP 22 was listening on IPv4 and IPv6. The SSH service was running with a disabled unit-file state, while ssh.socket was active and enabled. Socket activation explains why SSH is available with the service itself disabled.

The OpenSSH package is **1:9.6p1-3ubuntu13.19**. On **2026-09-30**, the effective server configuration was evaluated for `trappserver` and `ai-agent` using a temporary test host key. Ordinary users have password and public-key authentication enabled, keyboard-interactive authentication disabled, and root password login prohibited (`PermitRootLogin prohibit-password`, reported as `without-password`). The local drop-in requires a public key and disables password authentication and forwarding for `ai-agent` only. The live daemon was not reconfigured during this check.

Fail2Ban **1.0.2-3ubuntu0.1** is running. Its resolved on-disk configuration includes the SSH jail with a 10-minute ban interval, 10-minute observation interval, and five retries. The live jail and ban state could not be read without root access. See [host listeners and network separation](/todo/security-and-consistency#16-review-host-listeners-and-network-separation) for the remaining policy review.

## Host maintenance

NetworkManager, systemd-networkd, systemd-resolved, systemd-timesyncd, rsyslog, journald, and unattended-upgrades were running. System timers cover package updates, log rotation, filesystem checks, trimming, and package-database backups. These maintenance jobs do not establish application backup coverage.

The five-minute Caddy-to-UniFi DNS sync uses a user timer; see [Caddy setup](/infrastructure/caddy). Root and other users' cron jobs were not enumerated.

```sh
systemctl list-units --type=service --state=running --no-pager
systemctl --user list-units --type=service --state=running --no-pager
systemctl list-timers --all --no-pager
systemctl --user list-timers --all --no-pager
```

The snap Caddy service is disabled and inactive; the active proxy is Docker's caddy-v2 stack. LXD snap services were installed but inactive, with socket-based daemon activation. No LXD workloads were confirmed.
