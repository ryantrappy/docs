Komodo is the active container management interface. All application Compose projects were imported by **2026-09-30**. The retired Portainer and Watchtower containers were removed on 2026-10-02; their persistent data and deployment archives are retained for rollback. The detailed container settings below are a **2026-09-28 historical snapshot** unless noted otherwise.

## Management plane

Open [Komodo](https://komodo.ryantr.app) from the LAN. Caddy guards this hostname and forwards it to host port 9120. Core provides the management API and UI, Periphery manages the Docker host, and MongoDB stores Komodo state. Periphery and MongoDB have no host-published ports.

The API reports one server, **Local**, with Periphery version **2.3.3**. Core and Periphery use image tag `:2`; the tag does not identify an exact release.

Komodo's Compose file is `/home/trappserver/Documents/komodo/komodo/mongo.compose.yaml`. Core mounts its configuration and `/etc/komodo/backups`. Periphery mounts the Docker socket, `/proc`, and `/etc/komodo`. The `komodo_keys` volume is shared by Core and Periphery.

The separate Komodo MCP stack publishes host port 8003, protected by the LAN/server-local host policy. Its Streamable HTTP `/mcp` endpoint rejected unauthenticated initialization with HTTP 401 on 2026-10-02. Per-user OAuth identity derives scopes and resource permissions from Komodo. A separate `homelab-inventory` login has only read permissions; deployment administrators retain intentional write access. The MCP container has no Docker socket mount. See the [Komodo MCP project](https://github.com/MP-Tool/komodo-mcp-server).

## Other management and monitoring tools

Portainer's two Caddy routes were removed after the manager was stopped. The older `/data/compose/...` labels in the inventory identify the source used when containers were last created; current definitions are saved in Komodo. The private Portainer archive is under `/home/trappserver/komodo-migration/portainer-archive/`.

Uptime Kuma publishes host port 3001 and stores state in `/home/trappserver/Documents/uptime_kuma`. Configured monitors and notifications were not inspected.

Homelable provides infrastructure visualization and status monitoring. Direct backend/MCP ports now use the LAN/server-local host policy. MCP requires its application API key; unauthenticated initialization returns 401. Keys, signing secret and local password were rotated on 2026-10-02; retrieve replacements only from the protected local credential store. Its frontend publishes 3002, backend 8002, and MCP interface 8001. The backend uses the `homelable_backend_data` volume. See the [Homelable project](https://github.com/Pouzor/homelable).

No Caddy hostnames for Kuma, Homelable, or the Komodo MCP server were found.

## Persistence and updates

Retain Komodo's MongoDB volumes, keys volume, Core configuration, and backup directory. A backup directory mount does not prove that a backup is scheduled or restorable.

Watchtower and its historical replacement container were removed on 2026-10-02 after Komodo took ownership of application updates; protected source/rollback data remain. Komodo core, periphery, and MongoDB remain outside Komodo under their independent bootstrap Compose file.

Use [Service operations](/operations/services) for the maintenance workflow.
