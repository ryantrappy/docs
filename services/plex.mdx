## Server data

The observed server data directory is:

```text
/var/lib/plexmediaserver/Library/Application Support/Plex Media Server
```

| Item under the data directory | Purpose |
| --- | --- |
| `Preferences.xml` | Server settings; reading this file requires additional permission in the current shell |
| `Plug-in Support/Databases/com.plexapp.plugins.library.db` | Library database queried read-only for this inventory |
| `Plug-in Support/Databases/com.plexapp.plugins.library.blobs.db` | Companion database present on disk |
| `Metadata/`, `Media/` | Server metadata and media-support state |
| `Logs/` | Server logs |
| `Cache/` | Server cache; the configured transcoding directory was not verified |

Plex's server data directory is separate from the actual movie, television, and photo files. See the [Plex data-directory reference](https://support.plex.tv/articles/202915258-where-is-the-plex-media-server-data-directory-located/) for product context.

## Relationship to the media containers

The Docker media services are documented in [Media and downloads](/services/media). Radarr, Sonarr, SABnzbd, and qBittorrent manage media or downloads; Tautulli and Maintainerr can integrate with Plex.

Their presence does not prove the configured Plex integrations or automation rules are working. This inventory verified the native Plex service and its library roots without reading integration tokens.

## Database backups and recovery

Dated backup pairs for both the library and blobs databases were present for **2026-09-19, 2026-09-22, 2026-09-25, and 2026-09-28**, inside `Plug-in Support/Databases`.

These files establish that local backup copies exist. They do not establish off-host backup coverage or a tested restore.

Preserve the server data directory, settings, and the underlying library files when planning recovery. Handle the settings file as credential-bearing data. Follow the [Plex backup guide](https://support.plex.tv/articles/201539237-backing-up-plex-media-server-data/) and [scheduled database restore guide](https://support.plex.tv/articles/202485658-restore-a-database-backed-up-via-scheduled-tasks/) for the installed version. Stop the server before replacing database files and preserve `plex:plex` access.

CrashPlan also runs on this host, but its backup selection was not verified. See [Backups, power, and storage](/infrastructure/host-reliability).

## Routine inspection

```sh
systemctl status plexmediaserver.service --no-pager
systemctl is-enabled plexmediaserver.service
journalctl -u plexmediaserver.service --since today
dpkg-query -W plexmediaserver
curl -I http://127.0.0.1:32400/web/
```

A HTTP response checks the interface, not whether a movie plays successfully.

For an intentional maintenance restart:

```sh
sudo systemctl restart plexmediaserver.service
systemctl status plexmediaserver.service --no-pager
```

A restart interrupts active sessions. Plex package updates follow the host's package-management source, not a Komodo container deployment.
