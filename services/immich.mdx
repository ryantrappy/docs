Immich's four-container Komodo stack provides the photo and video service. All four containers reported healthy in the **2026-09-28** snapshot.

## Access and deployment

[Immich](https://immich.ryantr.app) is a public Caddy route to host port 2283. The machine learning, PostgreSQL, and Valkey services have no host-published ports.

Komodo's Compose file is `/etc/komodo/stacks/immich/compose.yaml`. All services share `immich_default` and use restart policy `always`.

The app and worker use the `release` tag. The database is PostgreSQL 14 with VectorChord and pgvectors extensions. Identify the installed app release before following a version-specific upgrade or restore procedure.

## Library and database

The upload mount points to `/etc/komodo/stacks/immich/library`; PostgreSQL data lives at `/etc/komodo/stacks/immich/postgres`.

Three existing directories under `/media/internal/fourteenTB/full_raid_backup` are mounted read-only: `Photos`, `dadExternal`, and `Photos from dads external`. A mount does not prove that the directory is configured as an external library inside Immich.

The worker uses the `immich_model-cache` volume. Server and Valkey anonymous volumes appear in the reference below.

## Backups and maintenance

Recovery needs the database and photo/video files together. Database dumps do not contain media. Preserve external-library files and their mount layout too. Use the [official backup and restore guide](https://docs.immich.app/administration/backup-and-restore/) for your installed version.

This inspection verified paths and Docker health; it did not verify backup scheduling or restore readiness.

```sh
docker logs --tail 100 immich_server
docker logs --tail 100 immich_machine_learning
docker logs --tail 100 immich_postgres
```

Use [Service operations](/operations/services) for maintenance.
