**Host implementation:** Root-owned `/usr/local/sbin/homelab-internal-ports` installs IPv4 and IPv6 rules in dedicated chains. `INPUT` protects native/host-network listeners and Docker's `DOCKER-USER` protects forwarded published ports. Conntrack matches the original host port after Docker DNAT, so mappings such as SAB's host `8282` to container `8080` are covered. Direct routing from non-LAN sources to private Docker container addresses is also restricted. Docker's own rules are preserved; UFW was not enabled or changed. See [Docker's recommended firewall integration](https://docs.docker.com/engine/network/firewall-iptables/).

**Persistence:** `homelab-internal-ports.service` is enabled and active. `/etc/systemd/system/docker.service.d/lan-port-access.conf` requires the policy to run before Docker. No production container restart was needed. Remote IPv6 access to the protected direct ports is blocked because Caddy currently defines only an IPv4 LAN. Update both policies before introducing an IPv6 LAN.

**Gateway implementation:** UniFi policy `6abbdea53f39a091c770be88`, **LAN-only UniFi management: block VPN**, blocks VPN → Gateway TCP `80,443`, always on, for both address families. LAN access is preserved; existing External, Hotspot, and DMZ default gateway blocks remain. The firewall snapshot comparison confirmed exactly one new policy with no changes to existing policies, zones, or groups. Readback places the new rule at index `10000`, before the predefined allow at `2147483647`. The separate ordering API returned 401; no reordering was performed.

**Verification:** Temporary network namespace probes showed all eleven host ports blocked from non-LAN IPv4 and IPv6 sources. A simulated LAN source reached all ten running ports. Packet counters confirmed both the native INPUT and IPv4 Docker DNAT forwarding paths were exercised. Public HTTPS returned 200 on both address families, and active internal Caddy routes remained available. Test containers, links, and routes were removed.

**Update — 2026-10-02:** Scrutiny now listens on loopback port `8081`; its Caddy LAN route returns HTTP 200. Direct LAN access to port `8081` remains unavailable. Boot dependency ordering was checked, but a production reboot was not performed. Gateway verification used configuration readback; an actual VPN/WAN client test was not available. Services outside Caddy's `internal-only` set, including the separate MCP listeners, were outside this requested change.

**Maintenance and rollback:** Implementation, verification results, and before/after snapshots are under `/home/trappserver/Documents/caddy_v2/internal-port-access/`; use its `README.md`. Reload the host policy with `sudo systemctl reload homelab-internal-ports.service`. The script's `remove` command removes only its own rules; disable boot installation and remove the Docker drop-in when rolling back permanently. Roll back UniFi by disabling or removing only the named policy. Avoid restoring an old full firewall snapshot over current Docker rules.
