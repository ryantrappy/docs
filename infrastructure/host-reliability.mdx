## CrashPlan

CrashPlan **12.0.0** is installed at `/usr/local/crashplan`. The enabled `crashplan.service` uses `/etc/systemd/system/crashplan.service` and starts `/usr/local/crashplan/bin/service.sh`. A root-owned `CrashPlanServic` process was present in the service's cgroup.

The unit reported `MainPID=0` despite the running engine. Check both the unit and its processes before treating that field as a failure:

```bash
systemctl status crashplan.service --no-pager
ps -eo pid,user,comm,cgroup | rg 'CrashPlan|crashplan'
journalctl -u crashplan.service -n 100 --no-pager
```

| Path | Purpose observed |
| --- | --- |
| `/usr/local/crashplan/conf` | Configuration directory; contents require additional permissions |
| `/usr/local/crashplan/log` | Contains service, history, and backup log files |
| `/usr/local/crashplan/cache` | Application cache directory |
| `/usr/local/crashplan/cp-version` | Installed version information |

The backup selections, destination, latest successful backup, retention, and restore history were not accessible in this inspection. Confirm them in the CrashPlan app before relying on it to protect Plex metadata, application configurations, or the media disks. A running engine alone does not establish backup coverage.

Use the official [service restart instructions](https://support.crashplan.com/hc/en-us/articles/8971613609997-Restarting-the-CrashPlan-app-service) and [log reference](https://support.crashplan.com/hc/en-us/articles/8959806429325-Read-CrashPlan-app-log-files) when troubleshooting. No restart or backup selection changes were made.

## Recovery checks

Before an application upgrade or storage change, confirm the application-specific backup, its destination, and a usable restore. Include the native Plex data directory and any host configuration that is required to reconstruct services. Keep media files separate from configuration and database backup planning.

For a host outage, check UPS status and disk mounts before restarting applications. Then verify Plex library access, CrashPlan backup activity, Docker application health, and off-host services independently. See [Service operations](/operations/services).
